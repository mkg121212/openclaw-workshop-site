WHAT IS OPENCLAW

OpenClaw 到底是什么

OpenClaw 是一个 AI 运行中枢。它连接聊天入口、模型能力和工具执行，把“问答”变成“可执行任务”。

OpenClaw 和网关的关系

OpenClaw 是整套系统，Gateway 是核心中枢。消息接入、模型调用、工具执行和状态管理都通过网关统一调度。

技术原理（大白话）

聊天软件把消息发给网关，网关再决定“哪个 Agent、哪个模型、哪些工具、什么策略”，处理完再把结果发回对应入口。

它解决的核心问题

  • 多平台接入重复开发
  • 多代理上下文容易污染
  • 配置、任务、安全策略难统一

它带来的核心价值

  • 统一接入聊天入口
  • 统一调度模型与工具
  • 统一运维和安全治理

WHY

OpenClaw 为什么会火

先看通用 Agent 公式，再看 OpenClaw 的实现差异。

通用 AI Agent 的基础公式

LLM（大脑） + Memory（记忆） + Planning（规划） + Tools（工具） + Reflection（反思）。

OpenClaw 的实现方式更“平民化”

通过 `soul.md`、`memory.md`、`SKILL.md` 直接改行为和能力，不依赖复杂数据库与向量检索，小白也能上手。

它不是“等你问”，而是“持续在干活”

Heartbeat 定时唤醒、Gateway 统一中枢、Lane Queue 控并发，让代理 24/7 更接近真人助理。

它强大的同时也有代价

本地执行与高权限意味着能力很强，也必须用清晰原则和边界去约束（例如在 soul.md 中定义安全规则）。

01

核心构成

OpenClaw 仍然遵循通用 Agent 架构，但把“可执行、可持续、可治理”放在第一优先级。

02

聊天即操作

在 Telegram / WhatsApp / Slack 发消息就能触发执行，不需要再切网页后台或额外 App。

03

真自主 + 持久运行

Heartbeat 定时检查任务，Gateway 防乱序，Lane Queue 防并发冲突，系统可长期稳定运行。

04

强能力也有风险

能操作本机文件和终端，必须有安全边界与规则，否则“很强”也可能“很危险”。

OLLAMA · FREE PATH

  • 不需要先付费
  • 可本地调试，风险低
  • 最适合验证链路是否打通

SKILLS CORE

为什么你的 OpenClaw 难用？

响应迟钝、功能缺失或无法执行任务，常见原因不是模型本身，而是核心 skills 没装好、没配好。

NET: MISSING? SEARCH: MISSING? SANDBOX: MISSING? MEMORY LOOP: OFF?

先理解：OpenClaw 依赖 skills 扩展能力

OpenClaw 是开源个人 AI 助手框架。核心能力通过社区 skills 模块扩展，没装对应技能就会出现“能聊但做不了”的情况。

优先级总原则

先补“联网 + 工具 + 安全 + 记忆迭代”四类基础能力，再装办公、开发、项目协作这类场景技能。

1. 联网能力（firecrawl-search / firecrawl-cli）

实时网页搜索与内容抓取。没有它，代理无法拿到最新资讯、价格、新闻，等于“活在过去”。

2. 技能自搜索（clawhub / super-skills）

让代理自己在 ClawHub 找技能并推荐安装，遇到不会的任务能主动找工具而不是直接放弃。

3. 主动迭代升级（self-improving-agent）

自动记录错误与教训，沉淀 LEARNINGS.md / ERRORS.md，让系统“越用越聪明”。

4. 安全沙箱（sandbox-security）

权限控制、恶意检测、沙箱执行。高权限代理不装安全层，风险极高。

5. Google 全家桶（gog）

集成 Gmail、Calendar、Drive、Docs、Sheets、Contacts，覆盖大量办公与日程场景。

6. 独立代理邮箱（agentmail）

为代理提供独立邮箱，支持自动化收发与验证，避免长期借用个人邮箱。

7. GitHub 集成（github）

仓库、Issue、PR、代码搜索、Review。开发者场景下几乎是必装。

8. 本地文件系统（filesystem-skill / local-files）

读写本地文件、批量处理、归档重命名等任务都依赖它。

9. 项目管理集成（linear / monday / notion）

根据团队实际选一个，打通任务流、看板与知识管理。

10. 错误/学习日志增强（learning-log / errors-md）

与 self-improving 配套，结构化记录失败原因，便于手动复盘和长期优化。

TOKEN OPTIMIZATION

付费使用优化 token 的技巧

OpenClaw 账单高不一定是模型贵，更多是配置在“全功率空转”。会配置的人，成本可差 5-10 倍。

HIGH TOKEN
→
PRUNE + ROUTE + CACHE
→
LOWER COST

1) 上下文累积未优化（No Pruning）

会话历史与多个记忆文件反复注入，简单任务也可能吃掉超大输入 token。

建议：启用 context-pruning / token-memory-optimizer，自动总结与修剪上下文。

2) 没有模型分层路由（Always Premium）

所有任务都打昂贵模型，连简单心跳任务也走高价推理。

建议：上 ClawRouter 或 smart-router，简单任务走低价模型，复杂任务再走高阶模型。

3) Prompt 缓存利用不足

缓存 TTL 短或未启用长保留，导致重复任务每次都重写上下文。

建议：启用长缓存策略（例如 long retention），并调优心跳间隔保持热缓存。

4) 心跳/Cron 触发过频

无交互时仍高频拉起完整上下文，夜间也持续烧 token。

建议：提高 heartbeat 间隔，非关键后台任务降频或路由到低成本模型。

5) 技能全量加载（Static Skill Loading）

未使用技能也注入 schema，技能越多基础 token 越高。

建议：动态加载/闲置卸载技能（dynamic-skill-loader）。

6) Session 文件膨胀

历史输出无限增长，老会话加载越来越重，响应慢且 token 暴涨。

建议：定期 /new 重置，配合 session-cleaner 与自动摘要。

7) 未启用本地 fallback

简单计算与本地总结也走云模型，白白付费。

建议：用 Ollama 本地小模型做 fallback，复杂任务再走云端高阶模型。

一句话结论

OpenClaw 成本高，往往是配置问题而非模型问题。把路由、缓存、上下文和后台任务调优好，成本会明显下降。

建议落地顺序

  • 先做上下文修剪
  • 再做模型分层路由
  • 然后优化缓存与心跳
  • 最后做动态技能与会话清理

TROUBLESHOOTING

基础课程常见问题

1) 安装完后命令不能用，怎么办？

先关闭终端再打开一次，然后执行 `node -v`、`npm -v`、`openclaw --help` 检查是否生效。

2) 为什么我还不能直接聊天？

因为还没接入聊天渠道。先选一个最简单的（如 Telegram），按官方步骤配置 token。

3) 本地模型和付费模型怎么选？

入门先用 Ollama 跑通流程；要稳定效果和真实业务质量，再切 Kimi 2.5。

4) 学完这节课下一步做什么？

先完成“一个渠道 + 一个模型 + 一次成功回复”的最小闭环，再逐步加插件和自动化。

FOR NORMAL USERS

对于普通人

OpenClaw 这波“大龙虾热”，让我想起两个时代。

90年代，组装电脑是一种潮流。有人帮你挑主板、显卡、内存，装系统、装驱动、装各种软件。那种“机器是自己拼出来的”的感觉，让人兴奋。拨号上网时刺耳的猫叫声，熬夜浏览外面的世界，等上几分钟，只为下载一张“好看”的图片。哈哈。

但没过多久，品牌整机开始普及。系统预装好，驱动配置好，普通用户不再关心显卡型号，也不再研究主板兼容。复杂度被封装了。

另一个时代是2000年代初，大屏 Windows Mobile 手机也给过类似的感觉：装软件、刷系统、像电脑一样折腾，手机竟然可以当电脑用，感觉未来到了。然后 iPhone 出现，复杂度被彻底隐藏。

今天的 OpenClaw，很像那个阶段。我们在配模型、调 API、管权限、算 token，像当年拼硬件一样兴奋。对极客来说是黄金时代；但对普通用户来说，这大概率只是过渡形态。

历史经验几乎一致：技术爆发期 DIY 繁荣 -> 平台整合 -> 普通人无感化使用。AI 也许还在“组装机时代”，但 Agent 的“iPhone 时刻”可能已经逼近。历史一再证明：真正改变世界的，是那个把复杂度吃掉的平台。
